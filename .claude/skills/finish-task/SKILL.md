## 1. Проверки Правила 2

```
cargo build --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy -p kvartik-app -p kvartik-ai --target wasm32-unknown-unknown --all-targets -- -D warnings
cargo test --workspace
cargo test -p kvartik-app -p kvartik-ai --target wasm32-unknown-unknown --bins   # браузерные, Chrome: окно и рамка помощника
GECKODRIVER=~/.cargo/drivers/geckodriver.exe cargo test -p kvartik-app -p kvartik-ai --target wasm32-unknown-unknown --bins   # они же в Firefox
trunk build --release          # в crates/app
node tools/browser/check.mjs   # собранный сайт в браузере; на машине — с --work C:/tmp/k<номер>
cargo deny check               # в CI всегда, на машине — по желанию
```

- Все девять — ровно то, что гоняет CI (`.github/workflows/ci.yml`). Новая
  проверка — сюда и в `ci.yml` вместе.
- В CI команды cargo — по замку, `--locked`, а после `trunk build` прогон
  сверяет `Cargo.lock` с коммитом (задача 85): Trunk и хук зовут cargo сами,
  без флага. Здесь флага нет — замок догоняет `Cargo.toml` сборкой
  (шаг 3); не догнал и ушёл в коммит — CI покраснеет словами cargo.
- `tools/browser/check.mjs` — на только что собранном `dist/`: части wasm,
  формы, копия, PDF, работа без сети (задача 60) и новая версия — включается
  сама и показывает окно «Что нового» (задача 67). Около минуты; провалы —
  в конце списком, код выхода 1.
- Браузерные тесты — двумя раннерами, окна и рамки ИИ-помощника
  (`crates/ai`, задача 111): у каждого число прошедших больше нуля — раннер при нуле тестов
  выходит с кодом 0 («no tests to run!»), — и браузер тот: строка
  «Running headless tests in Firefox» (или «in Chrome»). Упали с «session
  not created» — Chrome обновился, а chromedriver нет: skill `update-deps`.
  geckodriver лежит вне PATH (`~/.cargo/drivers/`): в PATH раннер взял бы
  его первым, и обычный прогон ушёл бы в Firefox.
- Тесты — по одному процессу cargo за раз: параллельные `build`, `clippy`
  и `test` ждут блокировку `target/` (Правило 8).
- Правились `.claude/hooks/` — ещё `node .claude/hooks/test.mjs`, и один
  живой отказ hook'а (Правило 2: проверка, которую не видели красной, не
  засчитывается).
- Упал тест — сказать прямо, с выводом, и не отправлять.

## 3. Четыре вопроса Правила 5

1. **Версия.** Поднять patch в `version` раздела `[workspace.package]`
   корневого `Cargo.toml` — и только там. Строка плана закрыта целиком —
   minor, но закрыта ли она, решает человек: предложить, а не поднимать.
   После подъёма — `cargo build --workspace`, чтобы `Cargo.lock` догнал.
2. **Формат данных.** Изменилось то, что лежит в IndexedDB или в копии, —
   `format_version`, миграция, образец копии прошлой версии в
   `crates/core/tests/backups/vN/` и тест (Правило 2). Новый вид записи —
   строка в `format::backup::KINDS`. Ставка, срок или порог — версия
   правил. Хранилища объектов или индексы — версия базы и обработчик
   обновления.
3. **README.md** — если изменение заметно пользователю или сдвинулся
   «План». Рефакторинг README не трогает.
4. **CLAUDE.md** — если выяснилось то, на чём споткнётся следующий:
   молчаливое поведение библиотеки или браузера, поправка закона,
   неочевидное решение. Коротко и с причиной; сначала поискать дубль.
   Механика — в skill, не в CLAUDE.md. Новый замер — в
   `docs/measurements.md`.

О новой версии и каждой правке README.md и CLAUDE.md — отдельной строкой
в отчёте.

## 4. Реестр (Правило 7)

- Удалить сделанную задачу целиком — запись и строку таблицы — и назвать
  удаление в отчёте.
- Столбец «Можно начать»: у каждой «нет» спросить, не ждала ли она этой
  задачи или того, что задача сделала (код, ответ, решение человека по
  дороге). Ждала — снять это ожидание: «да», если ждать больше нечего, или
  оставить остаток того, чего ждут, — и переложить строку в свою группу
  (сверху все «да», потом все «нет», внутри — порядок записей). Что стало
  «да» — строкой в отчёте.
- Поправить факты в соседних записях: сдвинувшиеся номера строк, исчезнувшую
  точку расширения. Смысла и судьбы чужой задачи не касаться.
- Найденное по дороге продолжение — новая задача, по важности, со строкой
  в таблице. Найденный дефект — не сюда: он чинится следующей задачей сразу
  после отправки этой. Без решения человека не починить — в реестр
  с пометкой `⚠ дефект, не функционал` и в отчёт.

## 5. CHANGELOG.md (Правило 10)

Сверху файла:

```
## <версия> — <ГГГГ-ММ-ДД>

### Добавлено | Изменено | Исправлено
- что видит пользователь, его словами и с причиной
```

Изменился формат данных — отдельной строкой: откроют ли прежние версии
новую копию. Изменились налоговые правила — отдельной строкой: что, с какой
даты, по какому закону. Без изменений в программе — одна строка «в программе
ничего не изменилось» и что изменилось вокруг. Рефакторинг, тесты, правки
CLAUDE.md и реестра в запись не идут.

И заметка «Что нового» (Правило 10) — сверху `crates/app/public/notes.json`:

```
{"version": "<версия>", "date": "<ГГГГ-ММ-ДД>",
 "hy": ["…"], "ru": ["…"], "en": ["…"]}
```

- Её видит человек в окне «Что нового», после обновления, на языке окна:
  один–четыре пункта по одному-два предложения — главное из записи
  `CHANGELOG.md`, без имён файлов, формата данных и проверок. Без изменений
  в программе — один пункт так и сказать: окно встанет и у этой версии,
  а без заметки прежняя программа не узнает новую сборку и не включит её.
- Пунктов на трёх языках поровну; армянские и английские термины — как
  в таблице строк (`crates/core/src/i18n.rs`): «Մատյան», «Պրոֆիլ», «Ledger».
  Тире — после неразрывного пробела (` —`), кавычки — языка.
- Заметки сверх `release::MAX_NOTES` (20) — удалить снизу.
- Проверяет `cargo test -p kvartik-app --test notes` (версия, языки, длина,
  правила записи) и `--test fonts` (знаки в шрифтах).

## 6. Коммит и отправка (Правило 11)

```
git add .
git commit -F <файл с сообщением вне проекта>
git push origin main
```

- Сообщение — `<версия>: <что изменилось>` из свежей записи CHANGELOG.md,
  последней строкой — подпись соавтора, которую называет оболочка.
  Файлом (`-F`), а не `-m`: в сообщении армянский и кириллица, а hook
  `guard.mjs` не пропустит текст, похожий на путь ключа.
- Перед `git add .` — `git status`: в коммит не должно попасть временное
  (пробы, логи, копии `dist/`) и `.claude/settings.local.json`.
- `push` в `main` — это выкладка сайта всем (с 0.0.29). Уходит только
  законченная задача с зелёными проверками. Не закончена или упал тест — не
  отправлять: сказать, что мешает и что `git status` показывает.
- Сервер отказал — никакого `--force`: сказать человеку.

Пачка задач (Правило 12): сведение по одной — `git merge --squash`,
проверки, версия, CHANGELOG, реестр, **локальный** коммит на каждую; одна
отправка на пачку.
