# Глазной прогон и замер

Правило — CLAUDE.md, Правило 2 («глазной прогон, но только своего»): смотреть
в браузере то, что задача добавила или изменила, на 360 и 1280 и на трёх
языках, — узко, но по-настоящему. Замер — Правило 1. Здесь — готовые
скрипты: писать их заново в каждой задаче не нужно. Chrome, серверы
и строки окна они берут из `tools/browser/` — оттуда же, что проверка
собранного сайта в CI (`tools/browser/check.mjs`, задача 60).

## Перед прогоном

1. `trunk build --release` в `crates/app`: service worker есть только
   в выпускной сборке (`src/platform/pwa.rs`), и прогон идёт по `dist/`.
2. Один раз на машине — wrangler из замка: `npm ci --ignore-scripts`
   в `tools/deploy` (`node_modules/` в `.gitignore`).
3. Номер задачи — `--task <номер>`: временное ляжет в `C:/tmp/k<номер>/`
   (профили Chrome, копии `dist/`, логи серверов), снимки —
   в `target/look/task-<номер>/`.

## Сценарии

```
node .claude/skills/browser-run/run.mjs <сценарий> --task <номер> [опции]
```

Опции:

- `--dist <папка>` — сайт (по умолчанию `crates/app/dist`); у `measure`
  можно несколько: сборки меряются по кругу. Сжатие — как у сайта
  (задача 109): wasm — копией уровнем brotli 11 из сборки (`*.wasm.br`,
  её отдаёт функция сайта), остальное — уровнем хостинга, 4
  (`HOSTING_QUALITY` в `tools/browser/serve.mjs`). `--quality 11` у `measure`
  — всё, у чего копии нет (у сборок до 0.0.154 — и wasm), уровнем 11, как
  мерили до 0.0.154: только для сравнения с прежними записями. Файлы, которые на сайт кладёт
  выкладка, а не сборка, — файл курсов ЦБ `app/rates.json` (задача 43), —
  оба сервера отдают образцом из тестов ядра (`DEPLOYED`
  в `tools/browser/serve.mjs`), если своего в папке нет: нужен курс другого
  дня — положите свой `app/rates.json` в копию `dist/`.
- `--routes home,documents,ledger,clients,profile,backup` — экраны именами
  (`home` — `#/`, остальные — `#/<имя>`, в том числе `documents/<id>`):
  Git Bash переписывает аргумент с `/` путём Windows. По умолчанию — `home`.
- `--langs hy,ru,en`, `--widths 360,1280`, `--themes light,dark` —
  по умолчанию все. `--lang ru` — язык окна сценариев, кроме `screens`.
- `--sample v6` — восстановить этот образец копии из
  `crates/core/tests/backups/samples.rs` перед снимками (по умолчанию —
  последний, `none` — без данных). Пароль образца станет паролем копий
  устройства.
- `--script <файл.mjs>` — свои шаги перед каждым снимком `screens`: модуль
  с `export default async (page, { lang, width, theme, route, t, shot }) => {…}`.
  `t("Key")` — строка на языке снимка прямо из `crates/core/src/i18n.rs`,
  `shot("имя")` — ещё один снимок. Методы `page` — в `tools/browser/cdp.mjs`:
  `eval`, `waitFor`, `click(текст или aria-label)`, `type(подпись, текст)`,
  `setFiles(селектор, файлы)`, `shot`, `shotOf(файл, селектор)`, `emulate`,
  `setLang`, `acceptLanguage`, `fresh`.
- `--port`, `--server own|wrangler`, `--runs 5`, `--path /app/`.

Снимки `screens` — без движения (`prefers-reduced-motion: reduce`, задача
86): во весь лист блок ниже первого экрана иначе снят бы до прокрутки — ещё
не выплывшим. Движение включает своё `--script`
(`Emulation.setEmulatedMedia` с `no-preference`), а середину перехода или
наведения снимает, заморозив анимации на нужной миллисекунде
(`document.getAnimations()`: `pause()` и `currentTime`), а не задержкой
снимка — её разброс больше самого перехода. Морозить только идущие
(`playState === "running"`): законченная с `fill: both` отмоталась бы назад,
и только по часам документа (`a.timeline === document.timeline`): появление
при прокрутке идёт по своей шкале. Переходы цвета под мышью (`CSSTransition`)
— не морозить, а довести до конца (`finish()`): их ведёт мышь машины, а не
переход. Середину перехода экрана снимать окном (`Page.captureScreenshot`
без `captureBeyondViewport`): слой перехода и закреплённое меню — у окна,
а `shot` снимает всю страницу (так снимали 2026-11-08; как `shot` ведёт
себя посреди перехода, не проверялось). Пример шага — замороженный переход
и цель нажатия каждой вкладки — `freeze` в `tools/browser/check.mjs`. В Firefox так не снять:
снимок WebDriver (geckodriver 0.37.1, Firefox 159) слоя перехода не видит —
прежняя сборка с дефектом прошла сравнение пикселей, — а `getAnimations()`
и `elementFromPoint` там работают; уже 500 точек окно Firefox без головы
не сужается (2026-11-08).
Мышь — `Input.dispatchMouseEvent`; у кнопки-пилюли угол скруглён, и точка
у края может оказаться мимо неё. События мыши есть везде, а мышь системы —
нет: у headless Chrome на Linux в CI `(hover: hover) and (pointer: fine)`
ложно, и что стили рисуют только с мышью (кружок у курсора), там не видно
(найдено 2026-11-06). `Emulation.setEmulatedMedia` эти признаки не
эмулирует (Chrome 157), поэтому проверка сверяется с `matchMedia` той
машины (`tools/browser/check.mjs`, «движение»); ложными, как в CI, их
делает эмуляция касания — `Emulation.setTouchEmulationEnabled`
(Chrome 157, 2026-11-08).
Видеокарты в CI тоже нет, и рисует Chrome там иначе: то же меню телефона
в другом состоянии страницы вышло иным (Chrome 156, 2026-11-08), а на
машине автора — тем же; у неё с `--disable-gpu` — на 33 точки сглаживания
иным (Chrome 157). Побайтно сравнивать только кадры
одного состояния: середину перехода — с тем же кадром, где слой перехода
прозрачен (`overMenu` в `tools/browser/check.mjs`), а не с кадром после.
Отрисовку CI на машине повторяет `CHROME_ARGS=--disable-gpu`.

## Почему скрипты устроены так

Всё ниже проверено вживую на машине автора (Windows 11, Chrome 155).

- **Ширина 360 и тема — только эмуляцией** (`Emulation.setDeviceMetricsOverride`
  с `mobile: true`, `Emulation.setEmulatedMedia` с `prefers-color-scheme`).
  Окно уже ~500 точек headless Chrome не сужает: `--window-size=360,…` даёт
  обрезанную справа страницу шириной 500. И тема берётся у Windows: при
  тёмной теме системы «светлый» снимок выходит тёмным (2026-10-11).
- **Честность ширины — числом.** На телефоне полосы прокрутки нет,
  и `document.documentElement.clientWidth` равен 360; на 1280 вертикальная
  полоса занимает 15 точек. Страница едет вбок, когда `scrollWidth` больше
  `clientWidth` — это `screens` и проверяет.
- **Снимка фоновой вкладки headless Chrome не делает** — команда висит:
  перед снимком `Page.bringToFront` (2026-10-12).
- **Снимок всей страницы** снимается за пределами окна
  (`captureBeyondViewport`): закреплённые меню и панель вкладок стоят там,
  где кончается окно в 780 точек, — посреди снимка. Это след снимка, а не
  раскладки (2026-10-14). Нужен раздел — `shotOf`.
- **Языки браузера для первого захода** — `Emulation.setUserAgentOverride`
  с `acceptLanguage` (`page.acceptLanguage`): он меняет и `navigator.languages`.
- **Язык окна** — `localStorage["kvartik.lang"]` (`hy`, `ru`, `en`)
  и перезагрузка: переход на `#/…` — внутри документа, и окно осталось бы на
  прежнем языке (2026-10-15). Пока язык не выбран, окно открывается экраном
  первого запуска.
- **Переход с `/` на `/#/x`** — тоже внутри документа: ни перезагрузки, ни
  проверки новой версии. Сначала `about:blank` (`page.fresh`, 2026-10-16).
- **Рабочий экран** — с 0.0.142 слова о хранении под экраном копии
  (`READY` в `run.mjs`): они в главном wasm и встают, когда база открыта
  и разделы прочитаны, а экран копии рисуется с первого показа (задача 91).
  До того (с 0.0.20) — поле выбора файла копии
  `input[type=file][accept=".json,application/json"]`: теперь оно встаёт,
  только когда экран копии показан. `measure` пишет и его (`old`): у сборок
  до 0.0.142 оба признака встают в один миг. Рабочий экран **новой**
  сборки — ещё и `script[type=module]` с адресом `/app/kvartik-app-…`: старая
  страница под новым service worker проходит все остальные проверки
  (задача 65, 2026-10-16).
- **Спрятанные экраны лежат в странице** с теми же кнопками: нажимать только
  видимую (`click` ищет по `getClientRects`). Счета, книга, клиенты
  и профиль — с первого показа (с 0.0.38), копия — тоже (с 0.0.142): до него
  в странице только их заголовок, и скрипт сначала открывает экран.
- **Поля Leptos** — `value` и событие `input`: его слушает `bind:value`.
  Файл — `DOM.setFileInputFiles` по `objectId` поля.
- **Выражение `Runtime.evaluate` — в своей функции**: у консоли одна общая
  область, и второй `const f` бросает исключение (2026-10-15).
- **Гасить только свой Chrome** — деревом своего процесса
  (`taskkill /pid … /T /F`), а не все `chrome.exe`: браузер человека работает
  рядом. Так же wrangler: у него дочерние `workerd`, и без дерева они держат
  порт (2026-10-15).

### Сервер

- **wrangler pages dev** из `tools/deploy` — тот же разбор `_headers` (CSP,
  кэш), `_redirects` и `404.html`, что у Cloudflare Pages: `/` — 302 на
  `/app/`, `/app` — 308, неизвестный адрес — ближайший `404.html` с кодом
  404 (проверено 2026-10-15 и 2026-10-16, wrangler 4.149.0). Он кладёт
  `.wrangler/` в текущую папку — поэтому идёт из `C:/tmp/k<номер>`.
- **Свой сервер** (`tools/browser/serve.mjs`) отвечает так же, но без `_headers`,
  и сжимает всё brotli при запуске: сжатие при первом запросе держало шесть
  соединений HTTP/1.1, и части wasm выглядели на 650 мс медленнее
  (задача 58).
- **Service worker живёт по адресу вместе с портом**: у сценариев свои
  порты, а не 8080 `trunk serve`. Профиль Chrome у каждого прогона новый.
- **«Без сети» — выключенный сервер**, а не эмуляция.
- **Новая версия** — копия `dist/` с изменённым файлом и `sw.js`,
  переписанным `kvartik-sw` (`TRUNK_STAGING_DIR=<копия>
  TRUNK_PUBLIC_URL=/app/ cargo run -p kvartik-sw -- public/sw.js` из
  `crates/app`; руками в Git Bash — с `MSYS_NO_PATHCONV=1`, иначе `/app/`
  станет путём Windows). Новой версией считается и правка файла корня: хэш
  сборки — по всему сайту. Готовая — `newVersion` в `tools/browser/serve.mjs`:
  без заметки новее работающей версии сборка сама не включится (задача 67).
  Копия — тот же wasm с теми же числами, поэтому окно «Что нового» встанет
  после неё, только если устройство помнит версию старше:
  `localStorage["kvartik.seen_version"]`. Пока окно не закрыто, оно встаёт
  на каждом открытии — так сценарий и снимает его на всех языках. Включить
  версию окно пробует один раз: `kvartik.update_tried` с той же версией —
  и сборка ждёт закрытия вкладок. Проверку новой версии без перезагрузки
  (с открытой формой) зовёт
  `navigator.serviceWorker.getRegistration().then((r) => r.update())`.
- **`trunk serve`** — программа по адресу http://127.0.0.1:8080/app/.
  Отладочная сборка снимает service worker, оставшийся от выпускной, сама,
  но открыться до этого успеет из его кэша — нужна одна-две перезагрузки
  (2026-10-12).
- **Прежняя сборка рядом** (переход с прежнего service worker, замер двух
  версий): `git worktree add --detach C:/tmp/k<номер>/old <коммит>`
  и `CARGO_TARGET_DIR=C:/tmp/k<номер>/old-target trunk build --release` там;
  сборка идёт параллельно с cargo в рабочей копии. Потом —
  `git worktree remove`.

### Установка

Вопрос об установке (`beforeinstallprompt`) приходит один раз — после
`load` — и только в основном контексте браузера: в отдельном
(`Target.createBrowserContext`, как в инкогнито) его нет вовсе. headless
Chrome присылает его и уже установленной программе — окно его там не
показывает. `Page.getAppId` и `Page.getInstallabilityErrors` проверяют
манифест без установки.

### Замер

- Способ — образец Lighthouse: `Network.emulateNetworkConditions` RTT
  562,5 мс, приём 1474,56·1024/8 Б/с, отдача 675·1024/8; процессор ×4;
  `Network.setCacheDisabled`; 412×823, DPR 1,75, `mobile`. Каждый заход —
  в своём контексте браузера: хранилище пустое. Рабочий экран ловит
  `MutationObserver`, вставленный `Page.addScriptToEvaluateOnNewDocument`;
  первый текст — `first-contentful-paint`; шрифты — последний пришедший
  `.ttf`.
- **Две сборки — в один день одним скриптом**, по кругу после прогревочного
  захода, медиана пяти. Прошлые числа из `docs/measurements.md` с другим
  Chrome или другим скриптом — не база для сравнения.
- **Машина — спокойная.** Сразу после `trunk build --release` и других
  прогонов тот же замер дал рабочий экран 3,38–3,53 с вместо 2,94
  (2026-10-16). Число, выпавшее из ряда, — перемерить, прежде чем звать
  регрессией.
- Каждый килобайт wasm после brotli — около 5,5 мс рабочего экрана на этом
  профиле (задача 58).
- **Мерить сборку с тем номером версии, который выходит.** Подъём версии
  сам по себе сдвигает разрез: тот же код с номером 0.0.117 вместо 0.0.116
  лёг в 24 файла wasm вместо 23, а главный — на 345 Б больше (2026-11-11);
  повторная сборка с тем же номером — те же байты.
- Седьмой файл первого захода ждёт свободного соединения целый круг сети:
  журнал сети (`Network.requestWillBeSent` и `loadingFinished`) это
  показывает.
- Установка service worker (`--sw`) — событие `controllerchange`
  страницы первого захода: `sw.js` кладёт в кэш весь сайт и после
  активации зовёт `clients.claim()`. Каждый лишний файл — лишний запрос по
  шести соединениям: 0.0.57 → 0.0.58 — 5,12 → 4,97 с при 64 → 65 файлах
  wasm (главный wasm легче на 40 КБ, задача 80, 2026-10-23).
- **Какие куски wasm новые.** Номера кусков `chunk_N` от сборки к сборке
  сдвигаются, хэш в имени — общий для всей сборки, а байты меняются почти
  у всех кусков: по именам и содержимому две сборки не сравнить. Сравнивать
  наборы частей: над каждым куском в загрузчике
  `dist/app/kvartik-split-*.js` — комментарий `/* book_part, … */`, и
  новый набор — это новый файл (`grep -h "^/\* .* \*/$"` по обеим сборкам,
  `sort`, `comm -13`). Что в новом куске — имена функций в разделе `name`
  того же куска до wasm-opt: `target/wasm32-unknown-unknown/release/kvartik-split/chunk_N.wasm`,
  номер — из загрузчика той же папки. Так нашлись `to_string` номера
  документа и итератор массива в выгрузке (задача 30, 2026-11-03).
- `Network.setBlockedURLs` — как сделать, чтобы часть wasm не загрузилась.
- Новый замер — записью в `docs/measurements.md`: версия, дата, что
  изменилось, числа, способ, версия Chrome.

### PDF

- Читалка Chrome (`--headless=new`) показывает PDF сама: снимок через
  секунды три после перехода на `file:///…pdf` — это страница
  (2026-10-14). Образцы счёта и акта на трёх языках пишет
  `cargo test -p kvartik-core look_pdf -- --ignored` (в `target/look/task-12/`).
- `pdftotext` (xpdf, `/ucrt64/bin`) кириллицу и армянский отдаёт только
  с `-enc UTF-8`.
- В уменьшенном снимке цифры вроде «0001» могут казаться цветными — это
  субпиксельная кайма, а не цвет.

### Ещё приёмы

- Копию, сделанную окном, читать через `fetch(a.href)` ссылки `blob:`.
- `navigator.share` в headless Chrome на Windows настоящий: перед нажатием
  «Отправить» подменить его заглушкой.
- Замирание страницы: кадры — циклом `requestAnimationFrame` (разрыв больше
  150 мс — запись), шаги wasm — `console.log` с `js_sys::Date::now()`, потом
  сопоставить; отладочный вывод убрать до коммита.
- Наполнить IndexedDB для нагрузочного прогона — из страницы:
  `indexedDB.open("kvartik")`, хранилище `records`, ключ `[вид, id]`,
  значение — строка JSON с `format_version`.
- Выпускная сборка, пересобранная в профиль с прежним service worker,
  показывает прежнюю: у сценариев профиль всегда новый, а своему —
  `unregister` и `caches.delete` перед снимками.
- Проверка CSP: `screens --server wrangler` собирает отказы CSP в ошибки
  страницы; запрос наружу (`fetch("https://example.com/")` через `page.eval`)
  обязан быть отвергнут.
